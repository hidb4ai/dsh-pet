# 可选的 PowerContext 长期记忆

[English](../../en/guides/memory.md) · 简体中文 · [文档首页](../README.md)

桌宠默认只使用原生近期对话。开启 PowerContext 后，每次聊天会召回相关的历史证据，成功完成的文本问答会在本地落盘后异步同步。每只宠物、每个服务地址分别保存 Scope 绑定和待同步队列。

当前宠物配置明确选择 PowerContext 时，由它独占召回与采集，不再调用 Cordis 注册的第三方记忆后端。切回原生模式后，按宿主扩展规则使用已注册的第三方后端；没有注册时使用近期对话。

## 快速开始：由桌宠管理本机记忆

**DSH 插件**：打开「设置 → 桌宠配置 → 本机长期记忆」，选择预设或填写生成模型、Embedding 模型与维度，点击「检查并启用记忆」。DSH 的聊天模型与凭据继续由宿主管理，此处的生成模型只用于记忆整理。页面显示实际准备步骤、就绪状态和等待时间，可取消准备、暂停、恢复或重试。其他语言界面目前使用英文文案，中文与英文完整提供。

安装和数据都位于 DSH 所在机器，而非访问网页的机器。本机记忆绑定默认宠物条目，自定义 pet pack 保留独立配置；同一条目内每只宠物仍有独立 Scope。首次设置使用下述默认预算，已有绑定保留调整值。插件卸载或 DSH 退出会停止它拥有的进程，重启自动恢复已启用服务。同一个数据目录一次只能由一个桌宠进程管理；从独立应用切换到 DSH 时先退出原应用，再在 DSH 中恢复。当前不采集 DSH 编程 Agent 会话。

**独立应用**按下述流程配置聊天及可选记忆；两种模式复用运行时与记忆生命周期：

独立应用第一次启动会打开「开始养鱼」。已有用户可以右键桌宠 →「打开 AI 设置」→「开始养鱼」；源码构建后也可运行 `pnpm standalone --setup`。无需先安装 Python、手写 `.env` 或单独运行记忆服务。

1. 已经能聊天的用户保持「沿用当前聊天配置」勾选，无需再填 Key。新用户选择服务商和地域，地址、模型会自动填写，再输入该地域的 Key。自定义服务，或 Embedding 使用另一家服务时，展开「高级选项：模型与 Embedding」。
2. 勾选「开启本机长期记忆」，点击「开始养鱼」。程序检查聊天和 Embedding 连接及向量维度，然后下载并校验 uv 0.9.26，在用户目录安装 Python 3.12 和 PowerContext 1.5.0。页面显示当前步骤和等待时间，安装期间可取消；聊天配置检查成功后，可以先去聊天。需要联网和系统 `curl`、`tar`；不会修改全局 Python 或 PATH。
3. 等待「长期记忆：服务已就绪」，点击「去聊天」。首次接入为默认宠物条目设置 4 轮近期历史、6000 字节近期正文与 4096 字节召回正文预算；恢复已有绑定时保留已调整的预算。其他 pet pack 的独立配置仍在「配置」中管理。

Qwen 预设包含北京、新加坡；地址与 Key 的地域须一致，切换预设或地域会清空输入中的聊天 Key。模型必须在自己的账户中可用，可按[官方地域与地址说明](https://help.aliyun.com/zh/model-studio/base-url)填写工作空间专属地址。预设 Embedding 的维度为 1024，详见[官方模型说明](https://help.aliyun.com/en/model-studio/qwen3-7-text-embedding)。

已保存的 Key 仅在原完整接口地址下复用，不会返回浏览器；不同服务地址需要自己的 Key。新设置检查失败时，原来的聊天配置和记忆服务继续可用；服务切换失败或被取消时会尝试恢复原服务，恢复失败会明确提示。取消首次安装会保留已通过检查的聊天配置，未完成的记忆准备可重试。

不勾选长期记忆时，只检查并保存聊天模型，不下载记忆服务。快速开始使用 OpenAI Chat Completions 兼容接口；Anthropic 聊天或已有远程服务继续使用下面的手动配置。

本机服务只监听 `127.0.0.1`，使用自动生成的 Bearer 令牌。密钥与令牌写入用户目录 `dsh-pet/powercontext/settings.json`，设置接口不回显。数据库、运行环境和缓存也留在该目录；端口与数据库身份在重启后保持不变。已有 embedding 的地址、模型和维度不能直接覆盖，以免混用向量空间。

再次启动桌宠时，已启用的本机记忆自动启动；退出桌宠时停止其拥有的记忆进程，不删除数据，也不安装开机服务。「暂停记忆」会切回原生近期历史并停止服务，刷新页面后仍显示暂停；点击「恢复记忆」重新启动。仅在高级设置里切换后端，不会立即停止已运行的本机服务。端口被占用或服务失败时显示错误，可按已保存配置重试；不会改端口另建一份记忆，也不会自动清空数据。

首次聊天与 Embedding 检查，以及后续聊天、记忆整理、检索可能产生模型费用。只开启 Atomic Memory 会话抽取与 embedding；不开启 Dream、Topic Memory 或 Profile 定时生成。服务就绪不代表新对话已经整理成记忆，后台检查间隔 30 秒也不是完成时限。本机后台生成超时为 120 秒，与前台召回的短超时独立；较慢模型可能需要多次生成才能完成整理。自动安装支持 Linux/macOS；Windows 随 PowerContext 保持实验性支持。

无图形桌面的机器不会自动打开浏览器或出现桌面角色；可在本机启动清单 `dsh-pet/standalone-runtime.json` 中找到带凭据的 `settingsUrl`，不要分享该地址。

## 手动连接已有服务

1. 部署 [PowerContext 1.5.0 Server](https://github.com/oceanbase/powercontext/releases/tag/powercontext-v1.5.0)，配置生成模型及所选检索方式需要的 embedding 模型，并开启 Memory 后台抽取。桌宠的「重试同步」只补传 Source，不执行抽取。
2. 在 DSH 设置页的「AI 模型与对话上下文」，或独立模式设置页的「长期记忆」中选择 PowerContext，填写服务地址并保存。支持本机 HTTP；远程地址必须使用 HTTPS。
3. 若手动连接的服务需要 Bearer 令牌，在启动桌宠宿主的环境中设置 `DSH_PET_POWERCONTEXT_TOKEN`。手动连接的令牌不写入宠物配置或 URL，也不会通过设置接口返回。请求不跟随重定向。本机自动服务使用自己的私有令牌，不覆盖此环境变量。
4. 告诉桌宠一条独特偏好，聊到它退出近期窗口，等待后台抽取后再追问。可在设置页刷新当前宠物的状态。

开启后仅采集后续成功问答，不自动导入旧聊天，不发送图片本体，也不采集周期碎碎念和梦话。对话发送到指定服务后是否进一步发送给模型提供商，由该服务的模型配置决定。

## 上下文预算

近期历史仍由 `chatMemoryRounds` 控制；另可设置近期正文与召回正文的 UTF-8 字节预算。近期预算为 0 时只按轮数限制，非零时保留预算内连续、完整的问答轮次。默认后端为 `native`，召回正文默认最多 4096 字节，召回及单次同步操作默认超时为 1500 毫秒。

聊天分界线使用宿主返回的 `contextRounds`，表示字节预算内实际选入下一轮的近期轮数。长期召回与这条线独立；检索线索包含预算内最近两轮和当前问题，帮助理解承接式追问。

字节预算不是模型 Token 限额，也不覆盖人设、本轮输入、时间或动作标记、图片和协议包装。减少近期输入不保证总费用下降，后台抽取、维护和检索也可能产生模型费用。本地历史文件和远端存储不会因输入预算而自动缩小。

## 同步状态与恢复

聊天页直接显示当前宠物的后端、待同步与已同步轮数，以及最近一次召回结果；切换宠物时重新读取，不沿用上一只宠物的状态。本机管理服务的就绪、准备中或暂停状态单独显示，点击「记忆设置」可回到开始养鱼页。可见页面约每 5 秒刷新，连接失败会显示未知状态并自动重连。

- **待同步**：成功问答已落盘，仍待服务接收。进程运行时每 15 秒尝试补传，每批最多两条；网络上传不占用聊天文件锁。
- **已同步**：Source 已被接收，不表示 Memory 已抽取，也不保证下一轮能召回。
- **未采集**：单轮序列化后超过 65536 字节；仍保留本地历史。
- **暂无相关记忆 / 暂不可用**：本轮没有召回结果，或服务失败、超时；聊天继续使用近期历史。

Scope 幂等键、Source ID 和精确载荷随 `memory.json` 持久化，重启后重试沿用原身份。更换服务地址不会把旧队列转发给新地址；切回旧地址可继续补传。HTTP 409 身份冲突会停止该绑定的补传，需要核对本地与服务端数据。不要通过删除记忆文件修复冲突；文件损坏或无法读取时，程序拒绝覆盖已有记录。

## 查看、更正与遗忘

聊天中打开「记得的事」后按需读取 active 原子记忆，每页十条。可以查看当前版本、最多三个来源及各 2000 字符摘录。来源可能是原始 JSON 对话；它是历史证据，不表示更正后的正文来自旧来源。读取失败会显示不可用，不会伪装成空列表。

更正通过内容版本校验保存新版本；遗忘使用内容版本和状态版本共同校验。若页面已过时，刷新核对后再操作。操作成功提示只在服务确认后出现；连接中断不能当作已成功。

遗忘将该原子记忆标为 `forgotten`，从长期召回中排除，保留原始来源与历史版本；近期上下文和新的对话仍可能出现相同信息。需要同时移出近期上下文时，再删除对应本机聊天。彻底清除远端证据需要另行管理服务端数据保留策略。

## 删除与停用

删除本地聊天会取消对应的未发送队列，但不会撤回已发送或正在发送的数据，也不会删除远端长期记忆。为继续定位远端记录，清空聊天后仍保留 Scope 绑定。可以在「记得的事」中逐条遗忘；这不是远端物理删除。删除宠物之前先管理它的长期记忆，避免失去该宠物的界面入口。

切回原生模式并保存后，不再发起新的召回或补传；已经开始的请求可能完成。本地历史、绑定和远端数据保留。

## 接口

- `GET /dsh-pet-7340/powercontext/setup`：DSH 本机准备状态、健康状态、脱敏模型配置及已保存记忆绑定；独立模式返回 `available: false`。
- `POST /dsh-pet-7340/powercontext/setup`：DSH 本机记忆的 `start/retry/stop/cancel`。`start` 只接受 `memory: true`，模型字段与下方独立设置接口一致；接受后返回 HTTP 200，通过 GET 轮询最终结果。无效输入、忙时或未提供管理能力时沿用插件业务失败格式 `200 + ok: false` 和固定错误说明；非 JSON 或跨站写入返回 415。接口不读取或回显 DSH 聊天凭据。
- `GET /dsh-pet-7340/chat/powercontext?pet=main`：读取已保存配置下的同步及召回状态，不返回对话正文或令牌。
- `POST /dsh-pet-7340/chat/powercontext?pet=main`：重试一批待同步记录并返回状态。
- `GET /dsh-pet-7340/chat/powercontext/memories?pet=main`：分页列出 active 记忆，`cursor` 取下一页；带 `id` 返回该条记忆来源。
- `POST /dsh-pet-7340/chat/powercontext/memories?pet=main`：传 `action`（`correct` / `forget`）、`id`、`revision`、`stateVersion`；更正还需 `text`（去空白后不超过 8192 UTF-8 字节）。

接口字段见 [OpenAPI](../../../openapi.yaml)。原有 `/chat/memory` 仍用于已删除宠物的本地残留记录。

### 独立模式首次设置接口

独立 CLI 与打包应用额外提供 `/standalone-ai/setup`，沿用本机 Host、同源和进程令牌校验。它不属于 DSH 插件 HTTP 契约，不在插件 OpenAPI 的 `/dsh-pet-7340/` 路径中。

- `GET` 返回 `stage`、`message`、`busy`、`canCancel`、`startedAt`（Unix 毫秒）、`chatReady`、`memoryReady`、`memoryEnabled`、`memoryRunning`、`configured`、`canRetry`、`retryDraft`，以及不含密钥的 `chat`、可选的 `serverUrl` 和 `models`。`chat.hasKey` 仅表示已保存密钥；`chatReady` 表示已有完整聊天配置，不是每次读取都请求模型。`memoryReady` 必须来自健康探测：启动时等待成功，运行中每 10 秒重新探测，结果超过 30 秒失效，进程退出或停止立即失效。它独立于本次操作是否成功，原服务仍可用时不会因新设置失败而变成 false。
- `stage` 包含 `idle/checking/checking_embedding/checking_runtime/downloading/installing_python/installing_memory/starting/restoring/saving/ready/error/stopped/cancelling/cancelled`。安装步骤对应实际工作，不提供估算百分比。
- `POST` 使用 JSON。首次设置传 `action: "start"`、`memory` 布尔值、`baseUrl`、`model`、`apiKey`；`memory: true` 时另需 `embeddingBaseUrl`、`embeddingModel`、`embeddingDimension`，以及必要时的 `embeddingApiKey`。未知字段拒绝。密钥留空或省略时，由服务端按完整接口地址匹配已保存密钥；Embedding 也可在与聊天地址相同时复用聊天 Key，不同地址且没有匹配的已保存 Key 时必须填写。
- `POST {"action":"retry"}` 重试尚未成功的本次设置；没有本次草稿时按已保存配置恢复记忆。草稿只保留在当前进程内，重启后不会自动执行失败的新设置。`POST {"action":"stop"}` 暂停本机记忆并关闭自动启动，保留数据库。`POST {"action":"cancel"}` 取消可取消的准备步骤；进入最终保存后 `canCancel` 为 false，取消请求返回 409。接受操作返回 HTTP 202，通过 GET 轮询；忙时其他写操作返回 409。
- 缺少能力令牌或来自不可信 Origin 返回 403；错误 JSON/字段返回 400，非 JSON 写入返回 415，其他方法返回 405。安装、模型和磁盘错误只返回固定说明，不返回原始子进程输出、服务商正文、密钥或令牌。
