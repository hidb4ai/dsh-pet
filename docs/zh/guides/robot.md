# 连接 Astra Pro 2.0 具身机器人

[文档首页](../README.md) · [English](../../en/guides/robot.md)

此功能位于开发源码中，**已发布的 `0.1.0-beta.1` 尚不包含它**，需要使用包含机器人桥接功能的新构建。DSH 桌宠聊天和独立版聊天共用控制面板；操作机器人无需先开启 PowerContext 或配置模型密钥。

## 已接通的能力

| 操作 | Astra Pro 2.0 接口 | 桌宠反馈 |
| --- | --- | --- |
| 检查连接 | 控制器状态码、状态描述和躯干／左右臂模式 | 连接状态和控制器描述 |
| 执行单个示教动作 | `ActionControl(action_id, command_id)` | 动作请求、可选桌宠动画、执行回执 |
| 执行示教动作序列 | `ActionManager(action_id[], command_description)` | 按顺序提交一组动作并显示回执 |
| 机器人语音播报 | `PublishTTSText(tts_text)` | 请求响应，不代表播报完成 |
| 停止机器人 | `PlannerControlStop`、`RobotSetMode(mode=5)`、`AgvEmergencyStop` | 分别显示规划器、上半身、底盘的响应 |

启用监测后，每五秒读取一次状态。控制器描述变化时，桌宠会显示气泡，机器人通过其他设备操作引起的描述变化也可反馈。当前使用的状态接口不能识别外部执行的具体动作，所以暂不能让桌宠逐一模仿机器人的任意手势。配置的桌宠动画在本应用请求对应动作时播放，不保证与实体动作同步完成。

普通聊天、自动碎碎念和模型输出不会自动下发实体动作。本版通过操作按钮执行厂家确认过的示教动作白名单，不提供关节坐标控制、笛卡尔运动、模式恢复或任意 SDK／系统命令。机器人操作不会自动写入 PowerContext 记忆。

## 准备环境

请厂家提供展会机器人的 **2.0 gRPC 地址及端口**、经过验证的示教动作 ID 和执行顺序、初始姿态及模式要求，以及停止后的现场恢复方法。不要直接使用示例文件中的 IP 或动作编号。

Python 运行在承载 DSH 或独立版的电脑上，该电脑需要能够访问机器人。如果 DSH 部署在容器中，Python 和 SDK 也要安装在容器环境中，配置路径必须对容器可见。厂家 SDK 使用明文 gRPC，应部署在受控的机器人网络中。DSH 的访问控制同样适用于机器人操作，独立版沿用本机登录会话校验。

推荐下载与宿主平台匹配的[完整依赖包](robot-bundles.md)，在面板选择 **内置环境**。包内已包含 Python、SDK 及全部依赖，不会修改系统 Python。

如果主动选择自定义环境，再将厂家提供的 `astra_grpc_clients-2.0.0-py3-none-any.whl` 安装到独立 Python 环境，放在**仓库和应用安装目录之外**。可从 Python 3.11 或 3.12 开始。SDK 生成代码对依赖的要求高于 wheel 元数据中的最低版本，下面的组合已通过本地 gRPC 测试服务验证。

Linux（请替换为实际 wheel 路径）：

```bash
python3 -m venv "$HOME/.local/share/astra-v2-venv"
"$HOME/.local/share/astra-v2-venv/bin/python" -m pip install \
  "grpcio==1.78.0" "protobuf==6.31.1" \
  /path/to/astra_grpc_clients-2.0.0-py3-none-any.whl
```

Windows PowerShell：

```powershell
$astraVenv = Join-Path $env:LOCALAPPDATA "astra-v2-venv"
py -3.11 -m venv $astraVenv
& "$astraVenv\Scripts\python.exe" -m pip install `
  "grpcio==1.78.0" "protobuf==6.31.1" `
  "C:\Downloads\astra_grpc_clients-2.0.0-py3-none-any.whl"
```

普通插件包仅携带适配脚本；完整平台包另外包含独立 Python 和 SDK 全部依赖。适配脚本直接使用 SDK 生成的协议模块，每次调用都有超时，只接受 `2.0.0`，不会回退到 1.0 协议。Windows 命令是安装指引，本次尚未验证 Windows 连接实体机器人的运行效果。

## 配置和操作

1. 打开桌宠聊天，展开 **Astra Pro 2.0 机器人 → 连接与示教动作**。
2. 填写机器人 `主机:端口` 或 `IPv4地址:端口`，完整包保持选择“内置环境”；自定义安装则选择“自定义 Python 环境”，填写其 Python 可执行文件的完整路径。当前不支持 IPv6 地址。
3. 添加易读的动作名称和厂家确认的动作 ID。多个 ID 用逗号分隔，会按顺序调用 2.0 动作管理接口。可选的桌宠动画名称必须与当前角色配置一致。
4. 勾选“启用连接监测”并保存。保存配置、重启宿主都会撤销动作授权；检查连接本身不会切换模式或驱动机器人。
5. 点击“检查连接”。允许动作需要状态未过期、控制器空闲码为 `520000`、躯干和左右臂均为自动模式 `1`。通过厂家工具设置机器人模式，面板不会自动切入自动模式。
6. 现场确认机器人静止、姿态和周围空间符合动作要求后，点击“现场已确认静止，允许下一次动作”，再点击“执行选中的实体动作”。每个请求都会消耗本次授权，失败或结果未知也一样。
7. 语音播报：填写文本并点击“让机器人播报”。需要已连接且当前没有其他应用命令在执行，不需要实体动作授权。
8. 展开“最近请求”查看回执。“控制器报告成功”只表示接口响应成功，不是独立的物理完成证明。超时、断线显示“执行状态待确认”，应用不会自动重试。

“停止机器人”在动作请求未返回时仍可点击，会启动独立进程，并分别尝试三个子系统的停止接口，某一路失败不妨碍其他路尝试。取消本地请求不代表机器人已静止，请现场确认，必要时使用实体急停。恢复模式需要现场操作，本应用不会自动恢复。退出宿主时，仅在应用命令仍待返回的情况下尝试停止；进程崩溃、断电或断网时无法保证停止。

## 数据位置与常见问题

- `$DSH_HOME/dsh-pet/astra-robot.json`：连接配置及动作白名单，使用私有文件权限。未配置 `DSH_HOME` 时，沿用宿主默认的 DSH 数据目录。
- `$DSH_HOME/dsh-pet/astra-commands.json`：最多保留最近 20 条回执，超出私有文件大小限制时继续缩减。回执不保存播报原文，但厂家返回的信息可能包含操作细节。
- 重启后，未确认的请求标记为未知，绝不重放。重启或修改配置会更新会话 ID。同一请求 ID、相同内容返回已有回执；相同 ID、不同内容会被拒绝。这是应用层去重，不代表机器人保证“恰好执行一次”。
- `bundled_runtime_unavailable`：请安装与宿主平台匹配的完整包；内置环境缺失时不会切换到系统 Python。
- `sdk_unavailable`：检查 Python 路径、SDK 是否正好为 2.0.0，以及 gRPC／protobuf 依赖版本。
- `robot_not_ready`：检查状态是否过期、空闲码以及三个模式。网络能 ping 通不等于动作就绪。
- `robot_storage_unavailable`：在控制停止的情况下修复文件权限或损坏的私有状态文件，然后重启。此时禁止动作；若已读取到机器人地址，仍允许发送停止请求。
- `robot_receipt_limit`：每次宿主会话最多保留 1,000 个请求标识。现场确认无动作运行后，重启宿主开启新会话。

## 验证范围

自动化检查覆盖单次授权、请求去重、状态过期、重启后的未知状态、独立停止和真实浏览器组件。厂家 2.0 wheel 还经过了**本地模拟 gRPC 服务**验证，覆盖构建后的 HTTP 宿主、Python 进程和 SDK 的完整调用链。这能验证协议序列化和应用行为，不能证明真机固件兼容、动作效果、避障、实际播报或停止距离。展会前仍需要用实体机器人完成现场联调。

开发检查：`pnpm test`、`pnpm test:robot`（需要 Python，不需要 SDK）、`pnpm test:ui`。虚拟环境、联调脚本和验证日志均应放在仓库外。接口见 [HTTP 文档](../reference/http-api.md) 和 [OpenAPI 契约](../../../openapi.yaml)。
